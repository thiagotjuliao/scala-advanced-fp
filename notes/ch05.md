# Capítulo 05 — IO como descrição

## Exercício 01 — o laço do IO

| peça | ideia |
| --- | --- |
| `flatMap` / `map` / `handleErrorWith` | Só constroem nós; quem executa é o `unsafeRun()`. Se o `flatMap` chamasse o laço, montar já rodaria o programa. |
| handler não reassocia | `FlatMap(HandleErrorWith(s, h), f)` → `HandleErrorWith(FlatMap(s, f), h)` muda o significado: o `h` passa a pegar o erro do `f`. Um handler tem escopo — vale até o fim do seu `source` e nada além. |
| pilha própria (`List`) | O laço carrega o `IO` atual e o que falta fazer. `FlatMap` empilha o `f` e segue com o `source`; `HandleErrorWith` empilha o `h`. Os frames moram no heap: um milhão não estoura. |
| a tabela | Valor: `f` aplica, `h` descarta. Erro: `f` descarta, `h` aplica. Pilha vazia: `Right(a)` / `Left(e)` — o erro vira valor, nunca `throw`. |
| `StepFunction = Either[Throwable, Any] => IO[Any]` | A minha escolha: cada frame já sabe reagir a `Right` e `Left`, e o laço só desempilha e aplica. A alternativa (um `enum` `Bind`/`Handle`) deixa a tabela no laço e descarta frames sem alocar nada. |
| `guard(io: => IO[Any])` | O `try` em volta de `loop(...)` não é chamada de cauda: o frame precisa ficar vivo para o `catch`. O `try` envolve só a chamada ao código de fora e devolve um `IO`; o `loop` vem depois. Por nome, senão o argumento é avaliado fora do `try`. `NonFatal`, não `Throwable`. |
| `Delay` = `loop(guard(Pure(thunk())), stack)` | O `Delay` só vira `Pure` ou `RaiseError`; a pilha fica com os outros casos. |
| `IO[Any]` no laço, cast no fim | O `IO` atual muda de tipo a cada passo (`Pure(4)` é `IO[Int]` dentro de um programa `IO[String]`). Entrada sem cast: `IO` é covariante. Saída com um cast: o que sai com a pilha vazia é o valor do programa inteiro. |
| cast do `f`, não do `h` | `X => IO[A]` não é `Any => IO[Any]` (entrada contravariante): cast, seguro porque o frame só recebe o que o `source` produz. `Throwable => IO[A]` já é `Throwable => IO[Any]` (saída covariante): sem cast. |
| `Stack[-A, +R]` do `IO.scala` | A pilha tipada: `-A` é o que o topo espera receber (o `X` deixa de ser escondido); `Bind[A, B, R]` liga a saída do `f` à entrada do `rest`; `R` é o tipo final, constante, e `Done[R]() extends Stack[R, R]` torna o cast do fim desnecessário. |

Onde travei:

- Achei que `try loop(...) catch ...` era chamada de cauda — o `try` cobre o
  `loop` inteiro, não só o `thunk()`.
- O primeiro `Delay` com pilha não vazia fazia `loop(guard(sf(Right(thunk()))), t)`:
  o `thunk()` lançava ao calcular o argumento, o `sf` (o handler) já tinha saído
  da pilha, e o erro passava por ele. A spec não pegava; virou o teste
  `a handler catches an exception thrown inside its program` na `main`.
- Confundi o tipo do `source` com o do programa inteiro (`Pure(4)` é `IO[Int]`).
- Um `???` depois do `match` virava o valor do `loop` e tirava a recursão da cauda.
